> **文档依据：** `docs/智识云-前端需求规格说明书.md`  
> **关联工程：** 现有 `rag-demo`（Spring Boot 2.7 + LangChain4j + PDFBox）将演进为本方案目标架构  
> **版本：** v1.0  
> **日期：** 2026-07-29

## 1. 方案概述

### 1.1 建设目标

构建与前端「智识云」产品能力对齐的后端服务，实现：

1. **企业账号准入**：邮箱/手机登录、注册审核、SSO（Azure AD）、JWT 会话  
2. **RAG 智能问答**：按知识库范围检索、带引用溯源、流式回答、无答案空态  
3. **多模态知识入库**：PDF 文本抽取 + 扫描件 OCR + 图片/图表 GPT Vision 理解  
4. **向量检索 + 业务检索**：Milvus Lite 语义检索 + MySQL 元数据/关键词检索  
5. **用户侧业务闭环**：会话历史、收藏、反馈、个人偏好、使用统计  

### 1.2 技术栈选型

| 层级 | 技术 | 版本建议 | 职责 |
|------|------|----------|------|
| 语言 | Java | 8 | 业务与 RAG 编排 |
| 框架 | Spring Boot | 2.7.x（建议 2.7.18） | Web / 配置 / 事务 |
| ORM | MyBatis-Plus 或 Spring Data JPA | 与 Boot 2.7 兼容 | MySQL 访问 |
| 数据库 | MySQL | 5.7 | 业务数据、文档元数据、会话、权限 |
| AI 编排 | LangChain4j | 0.31.x（与现网 demo 对齐，可后续升级） | Chat / Embedding / RAG 链路 |
| LLM / Vision | OpenAI 兼容 API（GPT-4o / GPT Vision） | — | 问答生成、图片理解 |
| Embedding | text-embedding-3-small（或兼容模型） | — | 文本向量化 |
| 向量库 | Milvus Lite | 嵌入式 / 本地进程 | 向量存储与 ANN 检索 |
| PDF 解析 | Apache PDFBox | 2.0.30 | 文本页抽取、渲染页图 |
| OCR | PaddleOCR | 服务化调用（HTTP/gRPC） | 扫描件/图片文字识别 |
| 安全 | Spring Security + JWT | — | 鉴权鉴权 |
| 文档 | Knife4j / springdoc | 可选 | API 文档 |
| 构建 | Maven | 3.8+ | 构建打包 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| 需求驱动 | API / 表结构对齐前端契约（SourceDoc、SearchResult、HistoryItem 等） |
| 检索可溯源 | 每个回答片段必须带回 `docId + page + excerpt + knowledgeBase` |
| 权限先行 | 向量检索与 SQL 检索均按用户可见知识库过滤 |
| 多模态统一入库 | 文本 / OCR / Vision 结果最终都归一为「带页码的 TextSegment」再 Embedding |
| 异步入库 | 大文件解析、OCR、Vision、向量写入走异步任务，避免阻塞上传接口 |
| Java 8 兼容 | 避免使用 Java 9+ API；LangChain4j / SDK 版本需锁定兼容线 |

## 2. 总体架构

### 2.1 逻辑架构

```
┌─────────────────────────────────────────────────────────────┐
│                     前端（智识云 Web）                        │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTPS / SSE
┌───────────────────────────▼─────────────────────────────────┐
│                 API Gateway / Spring Boot                     │
│  Auth │ Chat │ Search │ Browse │ Doc │ Fav │ Stats │ Admin*  │
└───┬─────────────┬───────────────┬───────────────┬───────────┘
    │             │               │               │
┌───▼───┐   ┌─────▼─────┐   ┌─────▼─────┐   ┌─────▼─────┐
│MySQL  │   │Milvus Lite│   │对象存储/本地│   │  AI 服务  │
│业务库 │   │向量检索   │   │文件仓库    │   │层（编排） │
└───────┘   └───────────┘   └───────────┘   └─────┬─────┘
                                                  │
                    ┌─────────────────────────────┼─────────────────┐
                    │                             │                 │
              ┌─────▼─────┐               ┌───────▼──────┐   ┌─────▼─────┐
              │LangChain4j│               │  PaddleOCR   │   │GPT Vision │
              │Chat+Embed │               │  识别服务    │   │多模态理解 │
              └───────────┘               └──────────────┘   └───────────┘
```

> \* Admin：文档上传、建库、权限配置可由独立管理端或内部 API 提供；用户侧前端不暴露管理入口，但后端需具备入库能力。

### 2.2 核心处理链路

#### A. 知识入库链路（Ingest）

```
上传文件
  → 落盘 + 写 kb_document（status=PROCESSING）
  → 文件类型路由
       ├─ 可抽取文本 PDF  → PDFBox 按页抽文本
       ├─ 扫描件/低文本 PDF → PDFBox 渲染页图 → PaddleOCR
       ├─ 图片（含图表） → PaddleOCR + GPT Vision 双通道
       └─ 其他（Word/Excel 等，二期）→ 转换或专用解析器
  → 文本清洗 / 分块（保留 page、docId、kbId）
  → Embedding 模型向量化
  → 写入 Milvus Lite + 回写 chunk 元数据到 MySQL
  → 更新文档 status=READY / FAILED
```

#### B. 智能问答链路（RAG Query）

```
用户提问 + knowledgeScope + conversationId
  → 鉴权 & 解析可见知识库列表
  → Embedding(question)
  → Milvus 检索（filter: kb_id in (...) [及可选 doc_id]）
  →（可选）MySQL 关键词召回融合 / Rerank
  → 组装 System Prompt + 上下文片段（带 [1][2] 引用）
  → LangChain4j Chat（建议 SSE 流式）
  → 落库 message / sources / 耗时统计
  → 低分或无命中 → 返回空态结构 + 联系人配置
```

#### C. 同文档问答

与全库问答相同，检索 filter 增加 `doc_id == {currentDocId}`。

### 3.2 LangChain4j

**职责：**

- `EmbeddingModel`：问题与文档块向量化  
- `ChatLanguageModel` / `StreamingChatLanguageModel`：问答生成  
-（可选）`EmbeddingStore` 适配层对接 Milvus Lite  

**与现有 demo 的演进：**

| 现有 | 目标 |
|------|------|
| `InMemoryEmbeddingStore` | 替换为 Milvus Lite EmbeddingStore |
| 同步 `chatModel.generate` | 增加 SSE 流式接口 |
| metadata 仅 source/chunk_index | 扩展 docId、kbId、page、fileType、chunkId |
| 单集合全库检索 | 按 kb 权限 filter + 同文档 filter |

**Prompt 规范（对齐前端）：**

```
系统角色：企业知识库助手「智识云」
约束：
1. 仅依据给定参考资料作答；资料不足则明确无答案
2. 关键事实后标注引用序号 [1][2]，与 sources 列表一一对应
3. 回答结构清晰（短结论 + 要点列表）
4. 声明：AI 可能出错，请以原文为准
```

无答案判定：检索命中为空，或最高分 `< min-score`，或模型输出命中「未找到」策略 → 返回前端空态结构（建议列表 + 联系人）。

### 3.3 Embedding

| 项 | 方案 |
|----|------|
| 模型 | `text-embedding-3-small`（维度 1536，可通过配置切换） |
| 调用方 | LangChain4j `OpenAiEmbeddingModel` |
| 入库 | 分块后批量 embed（注意限流与重试） |
| 查询 | 单次 embed(question) |
| 一致性 | 入库与查询必须使用同一模型与维度 |

**分块策略：**

1. 优先按页保留 `page` 元数据  
2. 单页过长再按 `chunk-size/overlap` 二次切分  
3. 块文本前缀可加：`《标题》第 N 页`，提升检索可读性与引用质量  

### 3.4 Milvus Lite

#### 选型说明

- **Milvus Lite**：适合单机 / 演示 / 中小规模知识库，部署轻、与 Java SDK 互通  
- 数据量增大后可无缝迁到独立 Milvus Standalone / Cluster（集合 Schema 保持一致）  

#### Collection Schema 建议

| Field | Type | 说明 |
|-------|------|------|
| id | Int64 / VarChar | 主键（与 MySQL `kb_chunk.id` 对齐或映射） |
| embedding | FloatVector(dim) | 向量 |
| doc_id | VarChar / Int64 | 文档 ID（标量过滤） |
| kb_id | VarChar | 知识库 ID：product/hr/tech/support |
| page | Int64 | 页码 |
| chunk_index | Int64 | 块序号 |
| text | VarChar | 原文片段（或仅存 MySQL，向量侧存截断） |
| tenant_id | VarChar | 预留多租户 |

**索引：** HNSW 或 IVF_FLAT；度量 COSINE。  

**检索 Filter 示例：**

```
kb_id in ["hr", "product"] and doc_id == "10086"   // 同文档问答
kb_id in ["hr"]                                    // 范围问答
```

**Java 集成：**

- 使用 `milvus-sdk-java` 管理集合、插入、检索  
- 封装 `MilvusEmbeddingStore` 实现 LangChain4j `EmbeddingStore<TextSegment>`，替换现有内存实现  

### 3.5 Apache PDFBox

| 能力 | 实现要点 |
|------|----------|
| 文本抽取 | `PDFTextStripper` 按页抽取（现有 `PdfParseService` 可复用增强） |
| 空页检测 | 页文本长度 / 有效字符占比低于阈值 → 判定为扫描页 |
| 页图渲染 | `PDFRenderer.renderImageWithDPI(pageIndex, 150~200)` 输出 PNG |
| 页数 | `document.getNumberOfPages()` 写入 `kb_document.page_count` |
| 安全 | 限制加密 PDF、超大页数；超时与内存保护 |

**输出统一结构：**

```json
{
  "page": 23,
  "text": "...",
  "sourceType": "PDF_TEXT | OCR | VISION",
  "confidence": 0.98
}
```

### 3.6 PaddleOCR

#### 部署方式（推荐）

独立 Python 微服务（FastAPI / PaddleServing），Java 通过 HTTP 调用，避免在 JVM 内嵌 Python。

**典型接口：**

```
POST /ocr/image
Content-Type: multipart/form-data
file: page.png

Response:
{
  "success": true,
  "text": "入职满1年不满10年，年休假5天…",
  "lines": [{ "text": "...", "score": 0.97, "box": [...] }]
}
```

#### Java 侧职责

- `PaddleOcrClient`：超时、重试、熔断  
- 对 PDF 扫描页、图片附件批量 OCR  
- OCR 文本进入同一分块 / Embedding 流水线  
- 失败标记页级 `parse_status=OCR_FAILED`，可人工重试  

### 3.7 GPT Vision

#### 使用场景

| 场景 | 为什么需要 Vision |
|------|-------------------|
| 流程图 / 架构图 | OCR 只能拿字，无法理解结构关系 |
| 表格截图排版混乱 | Vision 可结构化复述表格含义 |
| 产品图示 / 标识规范 | 需要语义描述供检索 |
| OCR 置信度低 | Vision 作为补充通道 |

#### 调用方式

使用 OpenAI 兼容多模态接口（模型如 `gpt-4o`）：

1. PDFBox / 上传图片 → 页图或原图  
2. Prompt：要求输出「可用于知识库检索的中文结构化描述」，包含关键数字、标题、步骤  
3. 将 Vision 文本与 OCR 文本合并（去重）后分块入库  
4. metadata 标记 `sourceType=VISION`  

**成本控制：**

- 仅对「低文本页 / 图片类型 / 显式图表页」触发  
- 可配置每文档 Vision 页数上限  
- 结果缓存到 `kb_page_content`，避免重复调用

## 4. 数据库设计（MySQL 5.7）

> 字符集：`utf8mb4`；引擎：`InnoDB`。  
> MySQL 5.7 不支持窗口函数部分写法，统计 SQL 需兼容 5.7。

### 4.1 ER 关系（简图）

```
sys_user ─┬─ user_preference
          ├─ conversation ── conversation_message ── message_source
          ├─ favorite_doc / favorite_answer
          ├─ answer_feedback
          └─ user_kb_permission

kb_library ── kb_document ── kb_page_content
                    └── kb_chunk （与 Milvus 向量对齐）
```

### 4.2 核心表结构

#### 4.2.1 用户与权限

```sql
CREATE TABLE sys_user (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  employee_no   VARCHAR(32)  DEFAULT NULL COMMENT '工号',
  name          VARCHAR(64)  NOT NULL,
  email         VARCHAR(128) DEFAULT NULL,
  phone         VARCHAR(32)  DEFAULT NULL,
  password_hash VARCHAR(100) NOT NULL,
  dept_name     VARCHAR(64)  DEFAULT NULL,

  status        TINYINT      NOT NULL DEFAULT 0 COMMENT '0待审核 1正常 2禁用',
  sso_subject   VARCHAR(128) DEFAULT NULL COMMENT 'Azure AD sub',
  created_at    DATETIME     NOT NULL,
  updated_at    DATETIME     NOT NULL,
  UNIQUE KEY uk_email (email),
  UNIQUE KEY uk_phone (phone)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE user_preference (
  user_id           BIGINT PRIMARY KEY,
  theme_mode        VARCHAR(16) NOT NULL DEFAULT 'system',
  notify_knowledge  TINYINT NOT NULL DEFAULT 1,
  notify_mention    TINYINT NOT NULL DEFAULT 1,
  default_scopes    VARCHAR(128) NOT NULL DEFAULT 'hr,product' COMMENT '逗号分隔',
```

#### 4.2.2 知识库与文档

```sql
CREATE TABLE kb_library (

  created_at    DATETIME NOT NULL,

  created_at    DATETIME NOT NULL,
  KEY idx_doc (doc_id),
  KEY idx_kb_page (kb_id, page_no)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### 4.2.3 会话、反馈、收藏

```sql
CREATE TABLE conversation (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id         BIGINT NOT NULL,

CREATE TABLE conversation_message (
  id               BIGINT PRIMARY KEY AUTO_INCREMENT,
  conversation_id  BIGINT NOT NULL,

  KEY idx_conv (conversation_id, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE message_source (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  message_id  BIGINT NOT NULL,
  ref_no      INT NOT NULL COMMENT '引用序号 1,2,...',
  doc_id      BIGINT NOT NULL,
  doc_title   VARCHAR(256) NOT NULL,
  kb_id       VARCHAR(32) NOT NULL,
  page_no     INT NOT NULL,

  score       DECIMAL(8,6) DEFAULT NULL

CREATE TABLE answer_feedback (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  message_id      BIGINT NOT NULL,
  user_id         BIGINT NOT NULL,
```

## 5. 核心服务设计

### 5.1 鉴权服务（Auth）

| 能力 | 设计 |
|------|------|
| 邮箱/手机登录 | 校验密码哈希（BCrypt），签发 JWT |
| 记住我 | accessToken 短时效 + refreshToken 长时效（或加长 JWT exp） |
| 注册 | 写入 `status=0` 待审核；审核通过后可登录（MVP 可配置自动通过） |
| SSO | OAuth2 Authorization Code 对接 Azure AD；回调绑定/创建用户 |
| 忘记密码 | 邮件/短信重置 Token（MVP 可先接口占位） |
| 鉴权传递 | `Authorization: Bearer <token>`；过滤器注入 `userId` |

### 5.2 入库编排服务（IngestPipeline）

```
DocumentIngestService
  ├─ PdfTextExtractor      (PDFBox)
  ├─ PdfPageRenderer       (PDFBox render)
  ├─ OcrService            (PaddleOCR Client)
  ├─ VisionService         (GPT Vision Client)
  ├─ TextCleaner / Chunker
  ├─ EmbeddingService      (LangChain4j)
  └─ VectorIndexService    (Milvus Lite)
```

**页处理决策树：**

```
if fileType == image:
    ocrText = OCR(image)
    visionText = Vision(image)   // 可配置
    merge → chunk → embed
else if pdf:
    for each page:
        text = PDFBox.extract(page)
        if text.tooShort:
            image = render(page)
            text = OCR(image)
            if stillPoor or hasChartHeuristic:
                text += Vision(image)
        save kb_page_content
        chunk + embed
```

### 5.3 RAG 问答服务

```
RagChatService.ask(userId, conversationId, question, scope, docId?)
  1. resolveVisibleKbIds(userId, scope)
  2. retrieve(question, kbIds, docId) → List<RetrievedChunk>
  3. if empty or lowScore → buildEmptyAnswer(kb contact)
  4. buildPrompt(chunks) → streaming generate
  5. persist messages + sources + usage_event(ASK)
  6. auto-title conversation（首问摘要）
```

**引用组装：**  
按检索排序赋予 `[1]..[n]`，`message_source` 持久化，响应结构对齐前端：

```json
{
  "answer": "根据公司规定…[1][2]",
  "latencyMs": 2300,
  "empty": false,
  "sources": [
    {
      "id": "s1",
      "docId": 12,
      "title": "《员工手册 2026 版》",
      "page": 23,
      "pageLabel": "第 23 页",
      "knowledgeBase": "人事制度库",
      "excerpt": "员工年假规定：…"
    }
  ],
  "emptyTips": [],
  "contact": null
}
```

### 5.4 搜索服务（混合检索）

对齐前端 Search：筛选、排序、高亮。

| 召回 | 说明 |
|------|------|
| 语义召回 | Milvus topK，按 kb filter |
| 关键词召回 | MySQL `LIKE` / FULLTEXT（5.7 InnoDB 全文需注意中文分词，MVP 可用 `LIKE` + 标题优先） |
| 融合 | RRF 或加权分数；去重按 doc_id |
| 排序 | relevant / newest(`updated_at`) / popular(`view_count`) |
| 高亮 | 对 excerpt 做关键词标记，返回 `highlights[]` |

### 5.5 文档阅读服务

| 接口能力 | 实现 |
|----------|------|
| 页内容 | 读 `kb_page_content`；增加 `view_count` |
| AI 摘要 | 对当前页文本调用 Chat 生成短摘要并短时缓存 |
| 相关片段 | 同 `doc_id` 向量检索 topN，或相邻页 + 相似 chunk |
| 同文档问答 | RAG + `doc_id` filter |
| 下载 | 鉴权后返回文件流 |
| 分享 | 生成有时效 shareToken |

### 5.6 统计服务

基于 `usage_event` + `conversation_message` 聚合：

- 提问次数、环比  
- 知识库分布  
- TOP 问题（按会话标题或问题归一）  
- 有帮助/没帮助占比  
- 活跃时段热力（按 hour 聚合）  
- 溯源习惯（VIEW_SOURCE / READ_DOC）  
- 成就进度（规则引擎按阈值计算）  

导出：生成 CSV/Excel（Apache POI 可选）。

## 7. 安全、权限与合规

| 项 | 方案 |
|----|------|
| 传输 | HTTPS；内网可 TLS 终止 |
| 密码 | BCrypt；禁止明文落库 |
| JWT | HS256/RS256；过期刷新 |
| 知识权限 | `user_kb_permission`；检索强制 filter |
| 文件访问 | 下载/页图需登录且有 kb 权限 |

| 审计（可选） | 登录、下载、管理上传记 `usage_event` / audit 表 |
| 隐私 | 反馈不对外展示身份；统计仅本人数据 |

## 9. 异步、性能与限流

| 场景 | 策略 |
|------|------|
| 文档入库 | `@Async` / 线程池；状态机 PENDING→PROCESSING→READY/FAILED |
| Embedding 批量 | 分批（如 16/32）+ 重试退避 |
| 问答 | SSE；超时（如 60s）；上下文 topK=5 |
| OCR/Vision | 独立超时；失败不阻断整篇（页级降级） |
| 接口限流 | 用户级 QPS（Bucket4j / 过滤器）；上传次数限制 |
| 缓存 | 文档摘要、热搜、知识库列表短缓存 |

**容量粗估（MVP）：**

- 文档量：数千篇以内  
- 分块：十万级向量，Milvus Lite 可支撑  
- 并发问答：十级并发；更高需独立 Milvus + 扩容应用实例

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Java 8 与新版 LangChain4j/Milvus SDK 不兼容 | 编译失败 | 锁定经验证版本（如 LC4j 0.31 + milvus-sdk 2.2.x）；升级需单独立项 |
| MySQL 5.7 中文全文检索弱 | 搜索体验差 | MVP：语义检索为主 + LIKE；二期接 ES |
| OCR/Vision 成本与耗时 | 入库慢、费用高 | 仅低文本页触发；限页；结果落库复用 |
| Milvus Lite 单机上限 | 规模瓶颈 | Schema 兼容，迁移 Standalone |
| 幻觉与错误引用 | 信任问题 | 低分空态、强制引用、前端免责声明 |
| 扫描件质量差 | 检索召回低 | DPI 提升、Vision 兜底、人工复核入口 |
