# 智识云 · AI 知识库 Agent 平台 — 后端技术方案

> **文档说明**  
> 本文档依据《智识云-前端需求规格说明书》v1.0 反推并细化后端实现方案，覆盖用户侧全部能力域（鉴权、问答、搜索、浏览、原文阅读、历史、收藏、个人中心、统计、反馈、帮助），并补充知识入库、解析、向量化、权限等后端必备能力。  
> **版本：** v1.0  
> **编写日期：** 2026-07-30  
> **产品名称：** 智识云 · AI 知识库  
> **对应前端：** `frontend-ai-knowledge-assistant`  
> **实现阶段：** 以 P0/P1/P2 与前端优先级对齐，优先打通「鉴权 → RAG 问答 → 溯源阅读」闭环

## 1. 文档概述

### 1.1 编写目的

- 明确后端技术选型、系统架构、模块边界、数据模型、接口契约与 RAG 链路设计
- 为前后端联调、测试验收、部署运维提供可落地的技术基线
- 与前端 Mock 契约对齐，便于逐步替换 `localStorage` / 静态数据

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 契约优先 | API / DTO 与前端实体（`SourceDoc`、`SearchResult`、`HistoryItem` 等）一一映射 |
| 只读用户侧 | 用户端无上传/删除/编辑知识入口；入库与权限走独立管理通道（内部 API / 管理脚本） |
| 可溯源 | 回答必须带 chunk 级引用（文档 ID、页码、摘录），支持原文定位 |
| 权限隔离 | 仅检索用户有权访问的知识库（`product` / `hr` / `tech` / `support`） |
| 流式优先 | 问答支持 SSE 流式输出，降低首 Token 等待感知 |
| 可演进 | MVP 单体 + Milvus Lite；后续可拆解析/OCR 微服务、升级独立 Milvus |

### 1.3 范围边界

| 范围内 | 范围外（本期可不做或弱化） |
|--------|---------------------------|
| 用户侧全部业务 API | 完整管理后台 UI |
| 知识入库内部 API / 批处理 | 移动原生 App |
| SSO（Azure AD OAuth2）对接 | 多租户 SaaS 计费 |
| RAG 全链路（解析→向量→生成） | 复杂工作流 Agent 编排（可预留） |

## 3. 总体架构设计

### 3.1 逻辑分层

| 层 | 职责 | 典型包 |
|----|------|--------|
| Interface | Controller、SSE、DTO、参数校验 | `controller` / `dto` / `vo` |
| Application | 用例编排、事务边界 | `service` / `application` |
| Domain | 领域模型、枚举、领域规则 | `domain` / `enums` |
| Infrastructure | MyBatis、Milvus、Redis、MinIO、OCR Client、LLM Client | `infra` / `mapper` / `client` |

### 3.2 部署形态（MVP）

**推荐：模块化单体（Modular Monolith）**

- 一个 Spring Boot 进程承载全部用户侧 API + 入库内部 API
- PaddleOCR 独立进程（Python），通过 HTTP 调用，避免 Java 侧嵌入 Paddle 运行时
- Milvus Lite 随应用或同机进程部署（开发/MVP）；生产可切独立 Milvus
- MySQL、Redis、MinIO 独立部署

**不推荐 MVP 阶段拆过多微服务**，以免拉高运维与联调成本。

### 3.3 核心业务链路

#### 3.3.1 知识入库链路（管理侧 / 内部）

```
上传文件 → MinIO 落盘 → 创建文档元数据(MySQL, status=PARSING)
       → 解析路由：
            文本 PDF  → PDFBox 按页抽文本
            扫描 PDF/图片 → 渲染页图 → PaddleOCR
            复杂图文页 → GPT Vision 生成结构化描述（可选增强）
            Word/Excel → POI
       → 清洗 / 分块（chunk，保留 pageNo、bbox/offset）
       → Embedding → 写入 Milvus Lite
       → 全文索引字段写入 MySQL（或 Redis Search / 后续 ES）
       → status=READY，更新页数、摘要
```

#### 3.3.2 智能问答链路（用户侧 P0）

```
创建/选择会话 → 选择知识库范围 scope
→ 写入 user message
→ Query Rewrite（可选）→ Embedding(query)
→ Milvus 向量检索（filter: kb_id IN scopes AND ACL）
→（可选）关键词召回融合 + Rerank
→ 组装 Prompt（系统约束 + 上下文 chunks + 引用编号规则）
→ LLM 流式生成（SSE）
→ 持久化 assistant message + citations
→ 无命中 → 返回 NO_ANSWER + 联系人引导
```

#### 3.3.3 知识搜索链路

```
keyword + category + sort
→ MySQL FULLTEXT / LIKE + 可选向量召回融合
→ 高亮摘录组装（excerptBefore / highlights / excerptAfter）
→ 权限过滤 → 分页返回
```

## 5. RAG 技术详细设计

### 5.1 解析策略矩阵

| 文件类型 | 主解析器 | 增强策略 | 页码/定位 |
|----------|----------|----------|-----------|
| 文本型 PDF | PDFBox `PDFTextStripper` 按页 | 表格区域可选 Tabula | `pageNo` 精确 |
| 扫描型 PDF | PDFBox 渲染 `PDFRenderer` → 图片 | PaddleOCR；低置信度页走 GPT Vision | `pageNo` + OCR box |
| 图片（png/jpg） | — | PaddleOCR + 可选 GPT Vision 描述 | page=1 |
| Word `.docx` | Apache POI | 标题层级保留 | 近似页（按段落序号映射） |
| Excel `.xlsx` | Apache POI / EasyExcel | Sheet 名 + 表头 + 行文本拼接 | sheetIndex |
| PPT `.pptx` | POI XML | 备注文本一并抽取 | slideNo |

**扫描件判定启发式：** PDF 页提取文本长度 < 阈值（如 30 字符）且存在较大 Image XObject → 判为扫描页。

### 5.2 分块（Chunking）策略

| 参数 | MVP 建议值 | 说明 |
|------|------------|------|
| chunk_size | 400~600 汉字 / ~800 tokens | 过短召回碎、过长噪声大 |
| overlap | 80~120 字 | 跨段问题连续 |
| 切分优先 | 按标题 / 段落 / 句号 | 避免半句切断 |
| 元数据必带 | `doc_id, kb_id, page_no, chunk_index, title, file_type` | 支撑溯源与权限过滤 |

**同页多 chunk：** 阅读器高亮用 `excerpt` 在页文本中二次定位（字符串匹配 / 模糊匹配）。

### 5.3 Embedding

| 项 | 方案 |
|----|------|
| 模型 | OpenAI `text-embedding-3-small`（1536 维）或 BGE-M3（1024 维，私有化友好） |
| 调用方式 | LangChain4j `EmbeddingModel` |
| 批处理 | 入库任务按 16/32 条批量 embed，失败重试 3 次 |
| 一致性 | query 与 document 必须同一模型、同一维度 |

### 5.4 Milvus Lite Collection 设计

**Collection 名：** `kb_chunks`

| Field | Type | 说明 |
|-------|------|------|
| `id` | Int64 / VarChar PK | chunk 主键（与 MySQL `kb_chunk.id` 一致） |
| `embedding` | FloatVector(dim) | 向量 |
| `doc_id` | VarChar | 文档 ID |
| `kb_id` | VarChar | `product`/`hr`/`tech`/`support` |
| `page_no` | Int64 | 页码 |
| `chunk_index` | Int64 | 文档内序号 |
| `text` | VarChar(65535) | 原文片段（也可只存 MySQL，向量库只存 id） |

**索引：** HNSW（`M=16, efConstruction=200`），度量 `COSINE` 或 `IP`（与模型归一化策略一致）。

**检索过滤表达式示例：**

```text
kb_id in ["hr", "product"] && doc_id in ["可选文档白名单"]
```

同文档问答时强制 `doc_id == {currentDocId}`。

### 5.5 检索与重排

**MVP 混合检索（推荐）：**

1. 向量召回 TopK=20（Milvus）
2. 关键词召回 TopK=20（MySQL FULLTEXT / LIKE on title+chunk）
3. RRF（Reciprocal Rank Fusion）融合 → TopN=8
4. （可选）Cross-Encoder / LLM Rerank → TopN=5 送入 Prompt

**阈值门槛：** 融合分 < τ 或无有效 chunk → 触发 NO_ANSWER。

### 5.6 Prompt 与引用规范

系统提示关键约束（摘要）：

1. 仅依据给定「参考片段」作答，禁止编造制度条款
2. 关键事实句末标注引用编号 `[1]` `[2]`，编号与片段列表一致
3. 片段不足以回答时输出约定 JSON/标记：`NO_ANSWER`
4. 回答使用结构化 Markdown（段落 + 要点列表）
5. 语言跟随用户（中/英）

**返回结构（服务端组装给前端）：**

```json
{
  "answerMarkdown": "...[1][2]",
  "citations": [
    {
      "index": 1,
      "docId": "doc_xxx",
      "title": "员工手册 2026 版",
      "page": 23,
      "knowledgeBase": "人事制度库",
      "knowledgeBaseId": "hr",
      "excerpt": "..."
    }
  ],
  "elapsedMs": 2300,
  "disclaimer": "AI 可能出错，请以原文为准"
}
```

### 5.7 多模态增强（GPT Vision）

**触发场景：**

- OCR 置信度低或版面复杂（流程图、组织架构图、带批注截图）
- 用户上传/库内图片型知识需要语义描述入库
- 阅读器「AI 摘要」对图表页生成可读概述

**流程：** 页图（PDFBox 渲染或原图）→ Vision API 生成「页面文字转录 + 结构化摘要」→ 作为 chunk 文本参与 Embedding。

**成本控制：** 仅对标记为 `NEED_VISION` 的页调用；结果缓存于 `kb_page_vision` 表。

### 5.8 PaddleOCR 服务接口（建议）

独立 Python FastAPI：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/ocr/image` | POST multipart | 返回 `{text, boxes[], confidence}` |
| `/ocr/pdf-page` | POST | 单页图片 OCR |
| `/health` | GET | 探活 |

Java 侧 `OcrClient` 使用 `RestTemplate` / `OkHttp`，超时 60s，失败重试与死信入任务表。

### 5.9 LangChain4j 集成要点（Java 8 + Boot 2.7）

| 能力 | 用法 |
|------|------|
| Chat | `OpenAiStreamingChatModel` → SSE 转发 |
| Embedding | `OpenAiEmbeddingModel` 或自定义 HTTP Embedding |
| Memory | 会话级：从 MySQL 加载近 N 轮，不依赖进程内 Memory（便于水平扩展） |
| Tools | MVP 可不启用 Agent Tool；预留「联系人查询」Tool |

**注意：** 流式场景勿把完整回答阻塞落库；采用「边推边缓冲，结束或取消时落库」。

**`usage_event`：** 埋点原始表（`ASK`/`OPEN_SOURCE`/`READ_COMPLETE`/`FAVORITE`/`FEEDBACK`…），供统计聚合  

**`stats_daily_user`：** 日聚合缓存，加速统计页  

#### 6.2.5 帮助与联系人

**`help_faq`：** question, answer, locale, sort_no  

**`biz_contact`：** library_id, name, title, wecom, ext_no —— 支撑无答案空态联系人卡片  

### 6.3 索引建议

- `chat_session(user_id, updated_at, deleted)`
- `chat_message(session_id, created_at)`
- `kb_document(library_id, category, updated_at)`
- `kb_chunk(doc_id, page_no)`
- `kb_document` 对 `title` FULLTEXT（ngram parser，MySQL 5.7 需确认 ngram 插件）
- `usage_event(user_id, event_time, event_type)`

## 7. 接口设计（与前端契约对齐）

### 7.1 统一规范

| 项 | 约定 |
|----|------|
| Base URL | `/api/v1` |
| 鉴权 | `Authorization: Bearer {accessToken}` |
| 成功响应 | `{ "code": 0, "message": "ok", "data": {} }` |
| 业务错误 | `code != 0`，如 `40101` 未登录、`40301` 无库权限 |
| 分页 | `page` 从 1，`size` 默认 20 |
| 时间 | ISO-8601 或 `yyyy-MM-dd HH:mm:ss`（前后端约定一种） |
| 流式 | `GET/POST` + `Accept: text/event-stream` |

### 7.2 Auth

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/login` | 邮箱或手机 + 密码；`rememberMe` |
| POST | `/auth/register` | 姓名+企业邮箱+密码 → status=待审核 或自动通过（可配置） |
| GET | `/auth/sso/authorize` | 跳转 Azure AD |
| GET | `/auth/sso/callback` | code 换 token，建立本地用户 |
| POST | `/auth/refresh` | Refresh Token 换发 |
| POST | `/auth/logout` | 吊销 Refresh |
| POST | `/auth/password/forgot` | 发送重置邮件/短信 |
| POST | `/auth/password/reset` | 重置密码 |
| GET | `/auth/me` | 当前用户（姓名/部门/工号/角色） |

### 7.3 Chat（P0）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/chat/sessions` | 新建会话；可带默认 scope |
| GET | `/chat/sessions` | 侧栏列表；支持 `keyword` 过滤标题 |
| GET | `/chat/sessions/{id}` | 会话详情 + 消息列表 |
| DELETE | `/chat/sessions/{id}` | 删除 |
| POST | `/chat/sessions/batch-delete` | 批量删除 |
| PATCH | `/chat/sessions/{id}/scope` | 切换知识库范围 |
| POST | `/chat/sessions/{id}/clear` | 清空消息 |
| POST | `/chat/sessions/{id}/share` | 生成 `shareToken` / 链接 |
| POST | `/chat/sessions/{id}/messages` | 发送用户问题（非流式，兼容） |
| POST | `/chat/sessions/{id}/messages:stream` | **SSE 流式问答** |
| POST | `/chat/messages/{id}/regenerate:stream` | 重新回答 |

**SSE 事件类型建议：**

```text
event: meta          data: {"messageId":"...","status":"SEARCHING"}
event: citation      data: {"index":1,"docId":"...","title":"...","page":23,"excerpt":"..."}
event: delta         data: {"content":"部分文本"}
event: done          data: {"elapsedMs":2300,"status":"OK|NO_ANSWER"}
event: error         data: {"code":50001,"message":"..."}
```

**NO_ANSWER data 附加：** `suggestions[]`、`contact{name,title,wecom,extNo}`

### 7.4 Feedback

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/feedback/helpful` | `{ messageId }` |
| POST | `/feedback/unhelpful` | issueType / comment / knowCorrect / correctAnswer |
| POST | `/feedback/rating` | `{ messageId, score:1-5 }` |

`issueType` 枚举与前端一致：`INACCURATE` / `WRONG_DOC` / `MISSING_KNOWLEDGE` / `INCOMPLETE` / `OTHER`

### 7.5 Search

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/search/knowledge` | `q, category(all\|product\|hr\|tech\|support), sort(relevance\|updated\|views), page, size` |
| GET | `/search/hot` | 热门搜索词 |

**响应字段对齐 `SearchResult`：** id, title, fileType, category, knowledgeBase, pages, updatedAt, views, excerptBefore, highlights[], excerptAfter, page

### 7.6 Browse

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/libraries` | 四库卡片：简介、文档数、标签、最近更新 |
| GET | `/libraries/{code}/documents` | `category, q, page, size` |

对齐 `LibraryDoc`。

### 7.7 Document

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/documents/{id}` | 元数据 + 是否已收藏 |
| GET | `/documents/{id}/file` | 下载/预览流（鉴权） |
| GET | `/documents/{id}/pages/{pageNo}/summary` | AI 摘要（缓存） |

### 7.8 History / Favorites / Profile / Stats / Help

## 8. 安全与权限设计

### 8.1 认证

| 机制 | 细节 |
|------|------|
| Access Token | JWT，有效期 2h，载荷含 userId、角色 |
| Refresh Token | 随机串存 Redis/DB，记住我 30 天 |
| 密码 | BCrypt（strength 10） |
| SSO | OAuth2 Authorization Code + PKCE（若客户端公钥场景）；后端换 token 后签发本地 JWT |
| 注册 | 企业邮箱后缀白名单；默认待管理员审核 |

### 8.2 授权

- 知识库 ACL：`kb_acl` + 角色兜底（如全员可读 `hr` 制度库可配置）
- 问答/搜索/浏览统一走 `LibraryAccessService.filterAccessible(userId, scopes)`
- 原文下载必须校验文档所属库权限
- 分享链接：只读短链，可设过期与访问次数；敏感库可禁止外链

### 8.3 防护

| 项 | 方案 |
|----|------|
| HTTPS | Nginx 终结 TLS |
| 限流 | Redis + 用户级问答 QPS（如 10 次/分钟） |
| 上传 | 仅 internal；类型白名单、病毒扫描（可后置） |
| XSS/注入 | 参数校验、MyBatis `#{}`、回答 Markdown 前端消毒 |
| 审计 | 登录、下载、分享、失败鉴权写入 `audit_log` |
| 隐私 | 反馈接口对外展示脱敏；需求承诺不公开身份用于绩效 |

## 15. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Java 8 + 新版 LangChain4j 不兼容 | 编译失败 | 锁定经测版本（如 0.31.x），升级需单独立项 |
| MySQL 5.7 FULLTEXT 中文弱 | 搜索不准 | ngram 解析器 + 向量混合检索 |
| Milvus Lite 生产稳定性 | 向量服务单点 | MVP 可用；上量迁独立 Milvus 集群 |
| OCR/Vision 成本与耗时 | 入库慢、费用高 | 仅扫描/低质页触发；异步队列；结果缓存 |
| LLM 幻觉 | 错误制度解答 | 强引用约束 + NO_ANSWER 阈值 + 免责声明 |
| SSE 网关缓冲 | 流式变「一次性」 | Nginx `proxy_buffering off`；超时拉长 |
| PDF 预览跨域/鉴权 | 前端无法加载 | 短时签名 URL 或同源 blob 拉取 |
