# 智识云 · 后端开发任务批次与提示词手册

> **文档说明**  
> 本文档依据《智识云-后端技术方案》将后端实现拆分为可独立交付的任务批次，并为**每一个批次**提供可直接粘贴给 AI Coding Agent / 开发同学的**详细提示词**。  
> **版本：** v1.0  
> **编写日期：** 2026-07-30  
> **关联文档：**  
> - `docs/智识云-后端技术方案.md`  
> - `docs/智识云-前端需求规格说明书.md`  
> **使用方式：** 严格按批次顺序执行；每一批开始前先确认上一批「完成门禁」已通过；将对应章节的「提示词」整段复制给 Agent，并附上技术方案相关章节路径。

### 0.3 全局约束（所有提示词默认继承）

以下约束**每一批提示词都默认生效**，无需在提示词中重复粘贴时仍应遵守：

1. **技术栈锁定：** Java 8、Spring Boot 2.7.18、MySQL 5.7、LangChain4j（建议 0.31.x）、Apache PDFBox 2.0.30+、Milvus（Lite / milvus-sdk-java 2.2.x）、MyBatis-Plus、Spring Security + JWT、Redis、MinIO。
2. **包名：** `com.zhishiyun.kb.*`（可在现有 `com.example.rag` 工程上迁移/重建，但最终包结构需与技术方案第 10 章一致）。
3. **API 前缀：** `/api/v1`；统一响应 `{ code, message, data }`；`code=0` 成功。
4. **用户侧只读知识：** 禁止对 C 端暴露上传/删除/编辑知识接口；入库仅 `/internal/**`。
5. **知识库枚举：** `all` / `product` / `hr` / `tech` / `support`，与前端完全一致。
6. **不要写无关 Markdown 文档**；除非本批次明确要求产出 SQL/配置文件。
7. **代码风格：** 少注释、不写空洞 try-catch；复用已有工具类；改动聚焦本批次范围。
8. **密钥：** API Key、密码仅走环境变量 / `application-local.yml`（gitignore），禁止提交真实密钥。

## B02 — 账号鉴权（登录 / 注册 / JWT / 记住我）

### 元信息

| 项 | 内容 |
|----|------|
| 目标 | 替换前端 localStorage 假登录；提供真实 Token 鉴权 |
| 依赖 | B01 |
| 完成门禁 | 登录拿 Token → 访问 /auth/me 成功；无 Token 访问受保护接口 401；登出后 refresh 失效 |
| 参考 | 技术方案 §7.2、§8；前端 §3.1 |

### 提示词

```text
你是资深 Java 后端工程师。请实现智识云用户侧鉴权模块 auth，对齐前端登录/注册需求与后端技术方案 §7.2、§8。本批次不做 SSO、不做忘记密码（仅预留接口 stub 也可，但标注 TODO）。

【功能范围】
1. POST /api/v1/auth/login
   - 支持邮箱或手机号 + 密码
   - 请求体：account, password, rememberMe(boolean)
   - 校验空值错误文案尽量贴近前端：请输入邮箱或手机号 / 请输入手机号 / 请输入密码
   - 成功返回：accessToken、refreshToken、expiresIn、user（name、deptName、empNo、roleCode、defaultKbScopes）
   - rememberMe=true：Refresh 30 天；否则 7 天（写入 sys_refresh_token，token 只存 hash）

2. POST /api/v1/auth/register
   - 字段：name、email、password
   - 企业邮箱后缀白名单可配置（如 @company.com）；MVP 可配置开关 autoApprove
   - 默认创建 user_preference：主题 system；默认知识库 ["hr","product"]；通知双开
   - 返回策略：待审核则提示不可登录；autoApprove 则直接登录返回 Token

3. POST /api/v1/auth/refresh
4. POST /api/v1/auth/logout（吊销 refresh）
5. GET /api/v1/auth/me（需登录）

【Security】
- Spring Security + JWT 过滤器：Authorization: Bearer ***
- 白名单：/api/v1/auth/login、register、refresh、knife4j、actuator/health
- 密码 BCrypt strength 10
- Access Token TTL 120 分钟，载荷含 userId、role
- 统一未登录返回 code=40101

【实现要求】
- 分层：AuthController / AuthService / JwtService / RefreshTokenRepository
- DTO 使用 validation 注解
- 登录成功写 audit_log（若表存在）
- 提供 Postman/HTTP 示例或 Knife4j 注解

【验收用例】
1. 错误密码 → 业务错误，不 500
2. 登录后 /auth/me 返回张明示例字段结构
3. 过期/非法 Token → 40101
4. logout 后 refresh 失败

【明确不做】
- Azure AD SSO
- 短信/邮件重置密码完整流
- 前端改动（可备注前端应存 Token）
```

## B03 — 知识入库冒烟闭环（PDFBox + Embedding + Milvus）

### 元信息

| 项 | 内容 |
|----|------|
| 目标 | 内部上传文本 PDF → 解析分块 → Embedding → Milvus → MySQL chunk 就绪 |
| 依赖 | B01（鉴权可对本批次 internal 使用 API Key） |
| 完成门禁 | 上传一份员工手册类 PDF 后 status=READY；Milvus 可检索到向量；kb_chunk 有 page_no |
| 参考 | 技术方案 §3.3.1、§5.1~5.4、§7.9 |

### 提示词

```text
你是资深 Java / RAG 工程师。请实现知识入库最小闭环 ingest（仅文本型 PDF）。对齐技术方案入库链路与 Milvus Collection 设计。

【接口（internal，API Key 保护）】
1. POST /api/v1/internal/ingest/documents
   - multipart: file, libraryCode(product|hr|tech|support), title?, category(faq|policy|manual)
   - Header: X-Internal-Api-Key
   - 流程：校验类型 pdf → 上传 MinIO（若 MinIO 不可用，可本地磁盘 Storage 适配器切换）→ 写 kb_document(status=PARSING) → 创建 ingest_task → 异步解析
   - 立即返回：docId, taskId

2. GET /api/v1/internal/ingest/tasks/{taskId}
   - 返回 status、progress、errorMsg

3. POST /api/v1/internal/ingest/reindex/{docId}
   - 删除旧 chunk/向量后重建

【解析与分块】
- 使用 Apache PDFBox 按页抽取文本（PDFTextStripper）
- 扫描页判定可先做启发式日志，本批次扫描页可跳过或标记 FAILED_PAGE，不接 OCR
- Chunker：chunk_size≈500 汉字，overlap≈100；按段落/句号优先
- 每个 chunk 必须含：doc_id, library_id/code, page_no, chunk_index, content
- 文档 pages、简易 summary（可取首页前 200 字）回写 kb_document；成功 status=READY，失败 FAILED

【向量】
- LangChain4j EmbeddingModel（OpenAI text-embedding-3-small 或可配置兼容 endpoint）
- 维度与配置 kb.milvus.dimension 一致
- 初始化 Collection `kb_chunks`（字段对齐技术方案 §5.4）：id、embedding、doc_id、kb_id、page_no、chunk_index、text（或 text 只存 MySQL）
- 批量 embed（16/32）失败重试 3 次
- milvus_pk 回写 kb_chunk

【工程要求】
- 异步：Spring @Async + 线程池，或 DB 任务表轮询；要有进度更新
- 配置化模型名、endpoint、apiKey
- 提供本地 Storage 与 MinIO 两种实现，配置切换
- 单元/集成测试至少覆盖：Chunker 边界、页码保留

【验收】
- 使用一份 ≥3 页的文本 PDF 走通 READY
- 用简单 Java main 或临时 internal search 接口验证向量 TopK 能返回含正确 page_no 的 chunk（临时接口本批次结束后可删除或保留在 internal）

【明确不做】
- Word/Excel/PPT
- PaddleOCR / GPT Vision
- 用户侧问答 API
```

## B04 — RAG 核心 + SSE 智能问答（P0 闭环）

### 元信息

| 项 | 内容 |
|----|------|
| 目标 | 打通「选库 → 提问 → 流式回答 → 引用溯源 → NO_ANSWER」 |
| 依赖 | B02, B03 |
| 完成门禁 | 前端可对接的 SSE 事件完整；引用含 docId/title/page/excerpt；无权限库不会被检索到 |
| 参考 | 技术方案 §3.3.2、§5.5~5.6、§7.3；前端 §3.2、§3.2.5 |

### 提示词

```text
你是资深 RAG 后端工程师。请实现 chat + rag 模块，完成智识云 P0 核心闭环。必须支持 SSE 流式输出，并与前端 ChatPage 契约对齐。

【会话 API】
1. POST /api/v1/chat/sessions — 可带 scope（默认取用户 preference.defaultKbScopes，若多选则逗号或 JSON；产品默认常为 hr）
2. GET /api/v1/chat/sessions?keyword= — 当前用户、未删除、按 updated_at 倒序；返回 title、scope、updatedAt、lastQuestion、rating
3. GET /api/v1/chat/sessions/{id} — 含 messages + citations
4. DELETE /api/v1/chat/sessions/{id} — 软删
5. POST /api/v1/chat/sessions/batch-delete — ids[]
6. PATCH /api/v1/chat/sessions/{id}/scope
7. POST /api/v1/chat/sessions/{id}/clear — 清空消息（保留会话）
8. POST /api/v1/chat/sessions/{id}/share — 本批次可先生成 shareToken 存库，返回链接字符串即可（完整校验放 B12）

【问答 API】
1. POST /api/v1/chat/sessions/{id}/messages:stream
   - Body: { "question": "..." }
   - Content-Type 响应：text/event-stream
   - 事件必须支持：
     event: meta       data: {"messageId":"...","status":"SEARCHING"}
     event: citation   data: {"index":1,"docId":"...","title":"...","page":23,"knowledgeBase":"人事制度库","knowledgeBaseId":"hr","excerpt":"..."}
     event: delta      data: {"content":"..."}
     event: done       data: {"elapsedMs":2300,"status":"OK|NO_ANSWER","disclaimer":"AI 可能出错，请以原文为准"}
     event: error      data: {"code":50001,"message":"..."}
   - NO_ANSWER 时 done 或独立事件需带 suggestions[] 与 contact{name,title,wecom,extNo}（从 biz_contact 按 scope 选择，优先 hr）

2. POST /api/v1/chat/messages/{id}/regenerate:stream — 基于原 user 问题重答，不丢失历史 user 消息

【RAG 流程（必须落地）】
1. 鉴权 + 会话归属校验
2. 写入 user message；更新 session.last_question；若 title 为空则用问题截断生成 title
3. LibraryAccessService：将 scope=all 展开为用户 ACL 内所有库；禁止检索无权限库
4. Embedding(question) → Milvus TopK=20（filter kb_id in scopes）
5. 分数阈值 kb.rag.score-threshold；不足则 NO_ANSWER（不要调用胡编 LLM，或调用但强制 NO_ANSWER 模板）
6. 取 TopN=context-n 组装 Prompt：
   - 仅依据参考片段作答
   - 事实标注 [1][2]
   - 不足则 NO_ANSWER
   - Markdown 结构化
7. LangChain4j Streaming ChatModel 流式生成 → 转发 delta
8. 结束后落库 assistant message + chat_citation；写 usage_event(ASK)
```
